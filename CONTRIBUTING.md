# Contributing

Thank you for helping make Spark diagnostics more useful and trustworthy.

## Before opening a pull request

1. Open or comment on an issue so the expected behavior is clear.
2. Keep diagnostic rules deterministic and include the evidence behind each finding.
3. Add tests using synthetic or explicitly redistributable event-log data.
4. Run `ruff check .` and `pytest` locally.

Do not commit production event logs, credentials, customer identifiers, or other sensitive data.
Small, focused pull requests are easier to review.
